  <action>
    Root cause hypothesis recorded in deferred-items.md (2 of 6 isolated failures, outcome pasted or reason foreground_changed instead of focus_changed): the test thread calls TwoEditWindow.FocusEdit(1) and immediately releases the delivery barrier. FocusEdit marshals to the window's own thread, so the paste check can run (a) before focus actually moved, giving pasted, or (b) after another window stole the foreground, giving foreground_changed. The test also uses EnsureForeground (window only) at the start, not the focus-aware variant, so the initial target capture may record a different focused control.
    Fix: (1) in the test use ForegroundHelper.EnsureForegroundFocus for the initial capture state and Requires.That when it cannot be achieved (honest skip, strict mode fails); (2) after FocusEdit(1) poll GetGUIThreadInfo until hwndFocus equals EditHandle(1) AND GetForegroundWindow equals the TwoEditWindow (timeout 3 s); if the foreground was lost, assert with a message that prints the foreground window title/class and the observed focus handle instead of silently proceeding; only then release the barrier; (3) add a TwoEditWindow.WaitUntilFocused(index, timeout) helper and a ForegroundHelper.Describe() diagnostic string used in assertion messages for both deferred E2E tests. Do not add retries or loosen the expected reason (focus_changed stays the required reason).
    Then write MANUAL-CHECKLIST.md in English with checkboxes and expected results for: Windows Terminal Ctrl+V paste (text pasted or manual-paste notice), elevated Notepad real UIPI deferral notice, real sleep then wake then dictate, real lock then unlock then dictate, clean Windows 10 profile or VM install without .NET SDK then dictate, logon autostart (reboot, confirm tray icon and hotkey), plus where to record the result (date, tester, outcome). Update deferred-items.md: mark the flake as root-caused with the hypothesis, the fix, and that confirmation happens in the final block.
    Do not run the E2E tests in this task.
  </action>
