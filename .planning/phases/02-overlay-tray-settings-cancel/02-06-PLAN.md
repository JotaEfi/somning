# Plan 02-06: First-Run Model Downloader & Verification

**Phase**: 02 - Overlay, Tray, Settings & Cancel  
**Wave**: 6  
**Requirements**: STT-07, APP-05  

## Objective
Implement first-run model download management with progress reporting, resume support via HTTP `Range` headers, SHA-256 verification against expected checksums, and graceful handling of retryable failures against local and remote servers.

## Requirements Covered
- **STT-07**: "First run with no model downloads it with progress, resume and SHA-256 verification against a local test server, reporting retryable failures."
- **APP-05**: User-facing progress text and notice messages in pt-BR.

## Tasks & Responsibilities

### Task 1: Core Model Downloader with Resume & SHA-256 (OpenCode)
- `ModelDownloadManager` in `Somning.Core.Model`:
  - `ModelDownloadRequest(Uri DownloadUri, string DestinationPath, string ExpectedSha256)`
  - `ModelDownloadProgress(long BytesDownloaded, long TotalBytes, double Percent, long SpeedBps)`
  - Resumes interrupted downloads using HTTP `Range: bytes={existingBytes}-` if destination or `.part` file exists.
  - Computes and verifies SHA-256 checksum after download completes. If checksum matches, moves `.part` to final destination; if mismatch, deletes corrupted file and throws `ModelChecksumMismatchException`.
  - Classifies errors: `IsRetryable(Exception ex)` for HTTP 5xx, timeouts, socket disconnects.
  - Exposes `IProgress<ModelDownloadProgress>?` and `CancellationToken`.
- Unit tests in `Somning.Core.Tests/Model/`.

### Task 2: First-Run App Integration & Local Server Tests (Antigravity & OpenCode)
- Integrate with `AppComposition`:
  - On startup before engine start (or when engine reports model missing), check if `EngineDefaults.ModelFile` exists in `SomningPaths.ModelsDir`.
  - If missing, initiate download with progress events notifying overlay: e.g. "Baixando modelo ({percent}%)...".
- Integration tests in `Somning.Integration.Tests/Model/ModelDownloaderTests.cs`:
  - Local `HttpListener` test server:
    - Test 1: Full successful download with verified SHA-256.
    - Test 2: Resumed download (interrupted halfway, client sends `Range: bytes={half}-`, server serves remaining bytes with 206 Partial Content, client verifies combined file).
    - Test 3: Checksum mismatch (server sends corrupted bytes, download manager rejects and deletes corrupted file).
    - Test 4: Transient retryable failure (server returns 503 on first try, downloader retries and succeeds).
