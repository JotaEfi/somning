# Plan 03-02: Mock HTTP Fixture Suite, Recording Retention & Cloud Adapter Integration

**Phase**: 03 - Cloud Engine  
**Wave**: 2  
**Requirements**: STT-05, STT-06, APP-02, APP-05, APP-06  

## Objective
Implement `CloudTranscriber` implementing `ITranscriber`, integrating with `AppComposition` to seamlessly route between local Whisper and cloud (Groq/OpenAI) based on `UserSettings.CloudProvider`, decrypting DPAPI API keys, keeping recordings on failure for retry, displaying distinct overlay notices, and running an automated pt-BR test suite against a local mock HTTP server.

## Requirements Covered
- **STT-05**: User can choose a cloud engine by entering an API key; cloud is opt-in only.
- **STT-06**: Cloud failures (no network, invalid key, rate limit, timeout) show a clear message and keep the recording for retry; no silent fallback to local.
- **APP-02**: Settings round-trip with DPAPI-encrypted API key.
- **APP-05**: User-facing error notices in pt-BR.
- **APP-06**: Metrics logger emits cloud metrics without leaking API keys.

## Architecture & Integration
1. **`CloudTranscriber : ITranscriber` (`Somning.App.Engine` or `Somning.Core.Cloud`)**:
   - Implements `ITranscriber`.
   - Delegates to `ICloudTranscriptionClient` with `CloudEngineConfig`.
   - Translates `CloudTranscriptionResult` into `EngineTranscription(Text, "pasted", ... Backend: "cloud-groq"|"cloud-openai", Model: ...)`.
   - On `CloudTranscriptionException`:
     - Maps to `EngineTranscription("", "error", ex.Message, ex.ErrorCode, Retryable: true, Backend: "cloud-...", Model: ...)`.
     - Critical: Does NOT fallback to local Whisper. Keeps spool WAV file intact so the user can retry.
2. **Composite / Router Transcriber (`RouterTranscriber : ITranscriber`)**:
   - Holds reference to both local `EngineSupervisor` and `CloudTranscriber`.
   - Routes `TranscribeAsync` based on `UserSettings.CloudProvider` ("none" -> local supervisor; "groq" / "openai" -> cloud transcriber).
   - If cloud is selected but API key is missing, throws / reports `invalid_api_key` notice.
3. **Overlay & EffectRunner Integration**:
   - In `EffectRunner.HandleOutcomeOverlay`:
     - Inspects error code from `EngineTranscription`.
     - If error is `no_network` -> `OverlayNoticeKind.CloudNoNetwork` ("Sem conexão com a internet").
     - If error is `invalid_api_key` -> `OverlayNoticeKind.CloudInvalidKey` ("Chave de API inválida").
     - If error is `rate_limit` -> `OverlayNoticeKind.CloudRateLimit` ("Limite de requisições excedido").
     - If error is `timeout` -> `OverlayNoticeKind.CloudTimeout` ("Tempo limite esgotado").
4. **Integration Test Suite (`Somning.Integration.Tests.Cloud.CloudIntegrationTests`)**:
   - Uses local `HttpListener` test server.
   - Fixture: `tests/fixtures/tracer/hoje.wav`.
   - Test 1: Groq happy path (mock returns `{"text": "hoje é sexta-feira"}`), verifies `EngineTranscription` with correct text, backend "cloud-groq", timing metrics.
   - Test 2: OpenAI happy path (mock returns `{"text": "hoje é sexta-feira"}`), verifies text and backend "cloud-openai".
   - Test 3: 401 Unauthorized -> error code `invalid_api_key`, recording preserved, no local fallback.
   - Test 4: 429 Too Many Requests -> error code `rate_limit`, recording preserved.
   - Test 5: Timeout / Connection refused -> error code `no_network` / `timeout`, recording preserved.
   - Test 6: Real API test (skipped if `GROQ_API_KEY` or `OPENAI_API_KEY` is not present in environment variables).
