# Plan 02-04: Overlay Pill Window & Live Waveform

**Phase**: 02 - Overlay, Tray, Settings & Cancel  
**Wave**: 4  
**Requirements**: OVL-01, OVL-02, OVL-03, AUD-03  

## Objective
Implement a lightweight, non-intrusive floating pill overlay window positioned at the bottom-center of the active monitor. It displays live mic-driven waveform visualization during recording, transcribing state, and pt-BR notices/errors, with verified Win32 styles (`WS_EX_TOPMOST`, `WS_EX_TOOLWINDOW`, `WS_EX_TRANSPARENT`, `WS_EX_NOACTIVATE`) preserving foreground focus at all times.

## Requirements Covered
- **OVL-01**: Floating pill overlay positioned bottom-center of active monitor.
- **OVL-02**: Non-intrusive window styles (`WS_EX_TOPMOST | WS_EX_TOOLWINDOW | WS_EX_TRANSPARENT | WS_EX_NOACTIVATE`). Automated tests verify styles, verify `GetForegroundWindow` is unchanged when showing/hiding, and test DPI scaling.
- **OVL-03**: Distinct visual states in pt-BR:
  - *Ouvindo...* (Listening with live waveform)
  - *Transcrevendo...* (Transcribing)
  - *Avisos/Erros* (Microfone não encontrado, Microfone bloqueado, Silêncio detectado, Nada detectado, Modelo ausente)
  - *Hidden* when idle.
- **AUD-03**: Live audio level (RMS/peak) computation from audio capture stream fed to overlay waveform visualization.

## Tasks & Responsibilities

### Task 1: Core Audio Level Tracker & Overlay State Machine (OpenCode)
- `AudioLevelCalculator` in `Somning.Core`:
  - Analyzes 16-bit PCM (or float) audio buffers and computes normalized RMS [0.0f .. 1.0f] with smoothing/decay.
  - Multi-bar level generator (e.g. 5 waveform bars varying with audio energy).
- `OverlayState` model in `Somning.Core.Overlay`:
  - `OverlayKind`: `Hidden`, `Listening`, `Transcribing`, `Notice`.
  - `NoticeReason`: `MicMissing`, `MicBlocked`, `SilenceOnly`, `NothingDetected`, `ModelMissing`.
  - Localized pt-BR text mappings (APP-05).
- Unit tests in `Somning.Core.Tests`.

### Task 2: Win32 Native Layered Overlay Window (Antigravity & OpenCode)
- Add required Win32 APIs in `NativeMethods.txt`:
  - `MonitorFromWindow`, `GetMonitorInfoW`, `MONITORINFO`
  - GDI / Layered window APIs (`UpdateLayeredWindow`, `CreateCompatibleDC`, `CreateDIBSection`, `AlphaBlend`, `SetWindowLongPtr`, `GetWindowLongPtr`, etc.) or GDI+ rendering.
- `OverlayWindowManager` in `Somning.Platform.Windows.Overlay`:
  - Runs on dedicated STA thread with hidden message pump.
  - Window created with:
    - `WS_EX_TOPMOST` (always on top)
    - `WS_EX_TOOLWINDOW` (not in Alt-Tab or taskbar)
    - `WS_EX_TRANSPARENT` (click-through)
    - `WS_EX_NOACTIVATE` (never takes keyboard or mouse focus)
    - `WS_EX_LAYERED` (per-pixel alpha transparency)
  - Monitor placement: bottom-center of active monitor with Per-Monitor DPI scaling.
  - Smooth rendering of rounded pill, text, status dot, and animated waveform bars.

### Task 3: App Wiring & End-to-End Style Verification
- Hook into `DictationHost` / `EffectRunner`:
  - Audio capture stream sends audio chunks to `AudioLevelCalculator` -> triggers overlay waveform update.
  - State transitions (`Listening` on recording start, `Transcribing` on stop, `Notice` on silence/error, `Hidden` on delivery/cancel).
- Integration tests in `Somning.Integration.Tests/Overlay`:
  - Window styles assertion test (`WS_EX_TOPMOST`, `WS_EX_TOOLWINDOW`, `WS_EX_TRANSPARENT`, `WS_EX_NOACTIVATE`).
  - Foreground window invariant test (`GetForegroundWindow()` unchanged before and after showing overlay).
  - Multi-DPI rendering assertion (100% and 150% DPI scale test).
