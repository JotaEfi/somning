  <action>
Per D-07 and research Pattern 5:
- `KeyEvent` record per `<interfaces>`.
- `KeyboardHook`: holds the HOOKPROC delegate in a field (GC safety). `Start()` creates a background thread "Somning.Hook" (AboveNormal priority) that calls SetWindowsHookEx(WH_KEYBOARD_LL, proc, null, 0), signals a ManualResetEventSlim when installed, then pumps GetMessage/TranslateMessage/DispatchMessage until WM_QUIT. `Dispose()` posts WM_QUIT via PostThreadMessage and joins with a 2 s timeout. Start() throws InvalidOperationException if the hook handle is invalid.
- `ChordTracker` (pure struct-like helper used inside the callback, no allocations): tracks Ctrl and Shift down state from hook events (VK_LCONTROL/RCONTROL/CONTROL, VK_LSHIFT/RSHIFT/SHIFT) because GetAsyncKeyState is stale inside the callback. Decision per event: when Space goes down while Ctrl and Shift are down, mark Space as "owned", suppress (return 1) and emit TriggerDown; while owned, further Space downs (auto-repeat) are suppressed and NOT emitted (the interpreter also ignores repeats defensively); Space up while owned → suppress, emit TriggerUp, clear owned. Releasing Ctrl/Shift is never suppressed.
- Callback rules: code < 0 → CallNextHookEx. Injected (flags & LLKHF_INJECTED) with dwExtraInfo == InputMarkers.Paste → CallNextHookEx without touching ChordTracker (D-09). Injected with InputMarkers.Test, or not injected → processed. Other injected input → processed (treat like physical). Emit via a bounded Channel (capacity 64, FullMode DropWrite) `TryWrite` with Environment.TickCount64 timestamp. No logging, locks, I/O or LINQ in the callback.
- `PhysicalKeyState.IsTriggerPhysicallyDown()` for the missed-key-up check, called only from the app loop.
- Test helpers per `<interfaces>`. `KeyboardHookTests` ([Trait("Category","Desktop")], each test starts with Requires.Desktop()):
  1. `Chord_is_suppressed_and_enqueued`: install ObserverHook first, then KeyboardHook; HotkeyInjector.Chord(50); within 1 s the channel yields TriggerDown then TriggerUp; ObserverHook saw VK_CONTROL/VK_SHIFT but zero VK_SPACE events.
  2. `Paste_marker_passes_through`: HotkeyInjector.PasteChord(); channel stays empty for 300 ms; ObserverHook saw VK_V down and up.
  3. `Space_without_modifiers_is_not_suppressed`: inject plain Space tagged Test; ObserverHook saw VK_SPACE; channel empty.
  4. `Auto_repeat_downs_are_not_emitted`: inject Ctrl+Shift+Space down, three more Space downs, then ups; channel yields exactly one TriggerDown and one TriggerUp.
  Ensure all injected keys are released in a finally block so a failing test never leaves modifiers stuck.
